# TEPIA GROUP — деплой і що тут відрізняється від Taralex

Коротка шпаргалка для розгортання цього проєкту на тому самому хостингу
(інший домен) + список того, що свідомо змінено, щоб два сайти не читались
як власність одного власника.

## 1. Головна відмінність в архітектурі: Nginx

Якщо Taralex вже займає порти **80/443** на цьому сервері своїм контейнером
`nginx`, другий контейнер `nginx` з цього проєкту **не підніметься** —
порт зайнятий. Два варіанти:

**Варіант A (рекомендовано, як і написано у вашій документації):**
Не піднімати `nginx`-сервіс з `docker-compose.yml` цього проєкту.
Натомість скопіювати обидва `server{}`-блоки з `nginx/nginx.conf` у
**вже існуючий** nginx.conf Taralex (там, де в нього зараз 2 блоки —
стане 4). Публічний сайт і адмінку цього проєкту змонтувати як ще два
volume в той самий контейнер:
```yaml
volumes:
  - /opt/tepia/public-site:/usr/share/nginx/html/tepia-site:ro
  - /opt/tepia/admin-site:/usr/share/nginx/html/tepia-admin:ro
  - /opt/tepia/error-pages:/usr/share/nginx/html/tepia-errors:ro
```
і поправити `root` / `alias` у скопійованих блоках відповідно.

**Варіант B:** якщо це окремий VPS/окрема IP-адреса — просто піднімайте
`docker-compose.yml` як є, конфлікту портів не буде.

`api` та `postgres` в цьому проєкті вже на інших портах (4001 / 5433),
так що вони точно не зіткнуться з Taralex, навіть в одному
docker-мережевому просторі.

## 2. Кроки розгортання

```bash
cd backend
cp .env.example .env
# відредагуйте .env: вкажіть SMTP_USER / SMTP_PASS (пароль додатку Gmail)
# JWT_SECRET і POSTGRES_PASSWORD вже згенеровані заново — НЕ ті, що в Taralex

docker compose up -d --build
docker compose exec api npm run migrate
docker compose exec api npm run create-admin -- "Ваше ім'я" you@tepiagroup.pl "надійний-пароль" admin
```

Після цього адмінка доступна на `admin.tepiagroup.pl`, сайт — на
`tepiagroup.pl`. Не забудьте DNS A-записи на обидва домени + випустити
сертифікати через certbot (окремо для кожного домену).

## 3. Права доступу після завантаження на сервер (як і в Taralex)

```bash
chmod 755 /opt/tepia /opt/tepia/backend
find /opt/tepia/backend/public-site -type d -exec chmod 755 {} \;
find /opt/tepia/backend/public-site -type f -exec chmod 644 {} \;
find /opt/tepia/backend/admin-site  -type d -exec chmod 755 {} \;
find /opt/tepia/backend/admin-site  -type f -exec chmod 644 {} \;
```

## 4. Що свідомо змінено (щоб сайти не виглядали як один власник)

- **Колірна палітра:** темно-коричневий/бронзовий (`#241611` / `#B87A3D`)
  замість темно-синього/золотого.
- **Шрифти:** Fraunces + Sora + IBM Plex Mono замість
  Bricolage Grotesque/Manrope/Space Mono.
- **Структура контенту:** замість "країни працевлаштування" — "галузі /
  practice areas", замість "етапи виїзду" — "5-етапний процес підбору
  керівників". Інша бізнес-модель (executive search замість трудової
  міграції), тому й інша логіка сторінок.
- **Верстка:** HTML розбитий на спільні `assets/css` та `assets/js`
  (i18n-рушій, взаємодії) замість інлайн-стилів в кожному файлі, як у
  Taralex — інший підхід до коду, менше візуальних "відбитків".
- **Домени, порти, назви контейнерів, JWT_SECRET, POSTGRES_PASSWORD** —
  всі згенеровані заново, нічого не перевикористано з Taralex.

## 5. Мови

- **Публічний сайт:** EN (за замовч.) · UA · DE · RO · RU —
  `public-site/assets/js/i18n.js`.
- **Адмінка:** мови контенту (вакансії/статті/тощо) тепер включають `uk`
  у всіх формах. Інтерфейс самої адмінки (кнопки, підписи) також
  перекладено на українську повністю, на додачу до EN/DE/RO/RU.

## 6. Що ще залишилось на ваш розсуд

- Реальні фото/лого — зараз стоїть наданий вами логотип TEPIA і плейсхолдери
  (SVG-іконки, ініціали замість фото команди) — казали, що зображення
  зміните самі.
- Демо-приклади в `admin-site/index.html` (текст-заглушки на кшталт
  "CFO мандат", видимі лише коли адмінка ще не підключена до бекенду) —
  косметика, не впливають на реальні дані з БД.
- SMTP-пароль, реальні адреси офісів, номери телефонів — зараз
  правдоподібні плейсхолдери (`office@tepiagroup.pl`, `+48 22 123 45 67`,
  `ul. Złota 44`) — замініть на реальні дані компанії.
